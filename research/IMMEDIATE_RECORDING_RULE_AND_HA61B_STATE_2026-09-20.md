# Immediate Research Recording Rule — 2026-09-20

## Operational decision

The project adopts **research → record → next research** as the default execution cycle.

Any review, self-critique, intermediate result, failure, discarded approach, or classification change that can alter the logical state or future research direction must be recorded **immediately**, before beginning the next calculation.

### Mandatory immediate-record triggers

1. **External or internal review**
   - what was confirmed;
   - what was incorrect;
   - which claim was weakened, closed, or superseded;
   - what new question/gap was exposed.

2. **Self-critical audit**
   - contradiction with the prior conclusion;
   - logical gap;
   - new source / obstruction / independence issue;
   - classification change.

3. **Intermediate research progress**
   - important calculation or lemma;
   - failed attack;
   - invalid approach;
   - reason for moving to the next authorized attack.

4. **Classification changes**
   Every downgrade/upgrade must preserve the transition and reason, e.g.
   `PASS / LOCAL → OPEN / LOAD-BEARING`.
   The earlier classification must be explicitly marked historical/superseded when it no longer controls.

5. **Cross-chat continuity**
   Records must be self-contained enough that a new session can reconstruct the state by reading:
   `RESEARCH_MAP.md → CURRENT_STATE.md → research/00_RESEARCH_LOG.md → relevant stage document → research/RESEARCH_CONTINUITY_PROTOCOL.md`,
   without relying on conversational memory.
